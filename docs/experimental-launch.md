# Experimental Mainnet release

The owner explicitly authorized a public experimental release without waiting for independent review. This changes the application release policy; it does not change the deployed immutable program, spending rules, keys, recovery schema or transaction authorization.

`experimental-ready` is separate from the reviewed `ready` state. `securityReview.status` remains `pending`; report URL, report hash and reviewed source/binary hashes remain null. The private `.mainnet/experimental-launch.json` record declares the operator's approval for the exact source digest, binary digest, Mainnet-v2 profile and program ID. Its public declaration appears in the deployment manifest. This is a publisher-policy declaration, not cryptographic spending authorization or a reviewer signature. The publisher already controls served application code.

Release still requires exact-source tests, the correct genesis, an executable source-matched immutable program, full bytecode hash, no upgrade authority, and all six independently fetched finalized owner lifecycle transactions. Every user operation checks deployment and chain state. Recovery export/verification, permanent operation commitments, durable signing intent, strict browser storage and locks, fixed amount/recipient/change destinations and identical-only retry rules remain unchanged. Missing or mismatched policy, code, deployment, or lifecycle evidence disables funding.

The website uses concise experimental language. Security details and the deposit approval explain that independent security review is pending. No audit, independent approval, hardware isolation or protection of the entire Solana network is claimed. Device security, application code, recovery secrets, program correctness, RPC integrity and Solana remain dependencies. SOL network fees and permanent record rent appear before approval.

[Current release evidence](experimental-launch.json) includes the actual production deployment and source digest. All 61 unit tests, three compiled-program matrices, and 18 public browser tests passed. Live read-only acceptance connects a disposable wallet interface, creates an encrypted local identity, exports/verifies recovery, and observes activation enabled; it requests no signature and submits no transaction. Actual partial/full withdrawal and rotation browser tests use compiled SBF in local VMs. The prior real owner Mainnet lifecycle retains its original source digest and six finalized transactions; it is not relabeled as a new flow.

PublicNode serves current accounts, fees and submitted transactions. Its historical index no longer returned the prior owner flow. A same-origin read-only function queries the pinned official Mainnet endpoint for only the six approved owner receipts and genesis. It strips browser Origin and credentials, checks method/receipt allowlists, and never accepts transactions, signing keys or recovery material. Both providers must pass full Mainnet genesis checks. Local compiled browser fixtures intercept this same history path; a bare Next development server without the function cannot validate a live Mainnet release.

The Mainnet SOL vault is independent of a token mint. The website displays the owner-supplied CA `66fEEkGSYVeBb2eTwsfmipZBvT3WY1ab9bRJTooSpump`. Its on-chain mint verification is pending; no initialized Mainnet account was found at verification. No token, liquidity pool, swap, staking operation, buyback, treasury or tradable asset was created for this release. Devnet funding remains disabled.

For a future code change: run `npm run verify:release`, create a deliberately authorized experimental policy record bound to the new tested source/binary (or supply a genuine exact-build independent report), then run `npm run release:mainnet`. Do not copy an authorization across programs, profiles or changed code. Static website publication must use the newly verified manifest. The record is not a secret but the surrounding `.mainnet` directory contains secrets and must never be uploaded.

Before broader real-money confidence: independently review the exact cryptographic implementation and recovery flows, strengthen signing isolation, complete reproducible-build and supply-chain review, fuzz adversarial program inputs, validate recovery across devices and network failures, improve RPC trust/availability, and establish operational incident procedures. The current release is experimental.
