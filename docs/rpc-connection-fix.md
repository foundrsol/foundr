# Browser Mainnet RPC connection fix

The user reported `Mainnet RPC could not be verified: Failed to fetch` at https://sonic-perseus-9a1cxls.vercel.app. This error means the browser failed to reach the RPC before obtaining a genesis hash. It does not establish a wallet network mismatch. Direct PublicNode CORS requests and genesis verification worked in the test environment; the user's exact browser transport failure could not be reproduced.

HTTPS production browsers now POST to `/api/mainnet-rpc` on the website's own origin. Vercel forwards requests to the explicit root `https://solana-rpc.publicnode.com/`. The initial bare-origin destination forwarded the original path and returned PublicNode's HTTP 404 `Resource not found`; the explicit root fixes that. Other HTTP methods receive 405. No cookies, redirects or cached RPC responses are allowed. Local HTTP and Node tools stay direct; Devnet continues to use `https://api.devnet.solana.com`.

Wallet connection stays separate from full-genesis and program validation. Diagnostics show the upstream provider, browser request URL, expected/received genesis, public wallet address, program ID and separate failure causes. Phantom's active network is still described as not exposed and not verified.

All key generation, encryption, recovery and one-time signing stay in the browser. Only public queries and signed transaction bytes use the relay. Vercel and PublicNode remain transport/data dependencies; genesis checking is not a light-client proof. The immutable Mainnet program and its original six finalized owner transactions were rechecked without spending additional Mainnet funds. The program binary is unchanged; original deployment/lifecycle records retain their original source hash. Public funding remains disabled pending a genuine independent review of the current exact build.

Verification passed 54 unit tests, three compiled-SBF matrices, both TypeScript checks, upstream blob verification and production builds. Local Chromium passed 16 checks with the production-only relay check skipped. All 17 checks passed on the public HTTPS deployment, including deliberately blocked direct provider access, wrong-network rejection, wallet-interface connection, encrypted identities, clean-browser recovery and the full lifecycle against compiled local SBF fixtures. Browser lifecycle fixtures are not Mainnet transactions. The original real Mainnet owner lifecycle is separately documented.
