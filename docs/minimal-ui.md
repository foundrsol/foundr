# Minimalist wallet interface

The current [SHELL website](https://sonic-perseus-9a1cxls.vercel.app/) uses a light default appearance with an optional saved dark mode, system typography, restrained controls and a small mint hermit crab. One central card puts the vault balance first and the connected-wallet balance below it. Create your vault, Add SOL and Send SOL share that card; Back up vault and Restore vault remain directly available. A short next-step line changes with setup status.

Repeated onboarding panels were removed. Network costs, deployment details and connection diagnostics expand on demand. Transaction history stays below the vault and shows a simple empty state until actual activity exists. The token area keeps the full contract address and clipboard action when a verified address is configured; it currently reports the address as pending. The public header has Wallet and How it Works, with no Devnet selector. The Mainnet banner remains explicit; direct developer routes retain their test-funds banners.

Forms and the optional Devnet protocol screen use the selected light or dark palette. Signing, backup verification, exact amount handling, rent/fee review, transaction states, Explorer links, RPC genesis checks and deployment gates are unchanged. Browser signing is still experimental and is not hardware isolation. The immutable Mainnet program is unchanged, and public funding remains disabled pending an independent exact-build review.

[Current navigation, release and layout evidence](guidance.json) and [public browser output](test-results/vercel-public-browser.txt) record the successful checks. Browser withdrawal fixtures execute compiled local SBF programs, not live Mainnet transactions. The original actual Mainnet owner lifecycle retains its original source hash and transaction records. This interface publication spent no Solana funds.
